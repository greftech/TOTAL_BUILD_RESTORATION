# Doc Gen

Sheet-bound Apps Script on the **TBR Job Numbers** spreadsheet. Adds a **TBR Docs** menu + sidebar that merges a project row's fields into Google Doc templates, produces a PDF + editable Doc per document type in the project's Drive folder, and logs every generation in two places.

Replaces the manual ~10-min-per-project copy/paste of the same fields (client name, address, loss type, dates) into the Contract, Work Authorization, Mold Waiver, and Certificate of Completion.

This is SPEC-TBR-01 — the templated-merge + dual-log foundation. Adobe Sign (SPEC-TBR-02) layers onto the same pipeline later.

## Files

| File | Purpose |
|------|---------|
| `Code.gs` | Menu, sidebar entry, `google.script.run` callbacks, merge engine, dual-log, one-time `initializeConfigSheet` bootstrap. |
| `Sidebar.html` | Vanilla HTML/JS sidebar (300px). Project dropdown, validation block, doc-type checkboxes, results. |
| `appsscript.json` | Manifest — Advanced Drive Service (v3) + OAuth scopes. |

## How it works

1. `onOpen` adds **TBR Docs → Open Sidebar** to the spreadsheet.
2. The sidebar defaults to the active row's project; a dropdown lists every row with both **Project Number** and **Project Name** populated.
3. On open / dropdown change / Refresh, the script validates the selected row:
   - The **Project Folder** column resolves to a real Drive folder.
   - Every column listed in the Config sheet's `Required Fields` tab (for any active doc type) is non-blank.
4. If validation passes, each active doc type is shown as a checkbox. Not-yet-generated types are pre-checked; already-generated types show `last generated: … by …` and are left unchecked (still selectable for regeneration).
5. **Generate Selected** — for each checked doc type, in sequence (whole run serialized by `LockService.getScriptLock()`, 30s timeout):
   1. Copy the template Doc into the project's `Documents` subfolder (get-or-created), named `(JobNumber) - (DocType) - YYYY-MM-DD HHmm`.
   2. `body.replaceText()` each `{{placeholder}}` from the Config `Placeholder Map`, formatting `date` / `currency` fields per the `Field Format` column.
   3. Export a PDF with the same base name into the same `Documents` subfolder. The editable Doc is kept alongside it for post-merge edits.
   4. Each doc type is atomic — a failure logs an error and continues with the rest. No rollback, no overwrite, no delete; every run is additive.
6. **Logging** (every success):
   - One row appended to the **TBR Document Activity** tab in the admin Config spreadsheet.
   - One human-readable line appended to the per-project **`(JobNumber) - (ClientName) Activity Log`** Doc at the project folder root: `May 18, 2026 9:42 AM — Contract generated by brian@… [PDF] [Doc]` (bracketed labels are live links).
   - Failures go to the Activity **tab only** with `status = error` — the per-project Doc is a completions-only narrative.

All Drive calls use the Advanced Drive Service with `supportsAllDrives: true` (+ `includeItemsFromAllDrives: true` on list calls), so project folders inside shared drives work end-to-end.

## One-time setup

1. Create the bound script: on the TBR Job Numbers sheet, **Extensions → Apps Script** (or add a new project there). Paste in `Code.gs`, `Sidebar.html`.
2. **Manifest:** Project Settings (⚙) → check *"Show appsscript.json manifest file in editor"* → replace its contents with `appsscript.json` here → save.
3. **Advanced service:** editor left rail → **+** next to *Services* → add **Drive API**, version **v3**, identifier **Drive**.
4. Create an **empty Google Sheet in the TBR admin folder** (the Config + activity log home). Copy its ID.
5. Paste that ID into `CONFIG_SHEET_ID` at the top of `Code.gs`; save.
6. From the editor's **Run** dropdown, run `initializeConfigSheet` once. It scaffolds 4 tabs in the admin sheet (idempotent — safe to re-run, but you won't need to). Authorize the new scopes when prompted.
7. In the admin sheet:
   - `Doc Types`: paste the real **Template Doc ID** for each of the 4 doc types.
   - `Placeholder Map` / `Required Fields`: the bootstrap seeds **Contract** only — add rows for Work Authorization, Mold Waiver, and Certificate of Completion.
8. Reload the TBR Job Numbers sheet — **TBR Docs** appears (alongside the existing job-number menu; the two bound scripts coexist).

`initializeConfigSheet` is intentionally **not** in the menu. It's a one-off, run from the editor.

## Admin Config spreadsheet schema

Four tabs, all on the single spreadsheet referenced by `CONFIG_SHEET_ID`:

**`Doc Types`** — one row per document type.

| Doc Type Name | Template Doc ID | Template Version | Active |
|---|---|---|---|
| Contract | `1AbC…` | 1 | yes |

**`Placeholder Map`** — one row per placeholder per doc type.

| Doc Type | Placeholder | Source Column | Field Format |
|---|---|---|---|
| Contract | `{{client_name}}` | Project Name | text |
| Contract | `{{loss_date}}` | Date of Loss | date |

`Field Format`: `text` (default), `date` (→ `MMMM d, yyyy`), or `currency` (→ `$1,234.56`). `Source Column` must match a header on the TBR Job Numbers sheet.

**`Required Fields`** — one row per required content column per doc type. Generate is blocked while any is blank on the selected row.

| Doc Type | Source Column |
|---|---|
| Contract | Project Name |
| Contract | Date of Loss |

**`TBR Document Activity`** — append-only log, written by the script.

`Timestamp · Job Number · Client Name · Doc Type · Template Version · Generated By · Editable Doc URL · PDF URL · Status · Error Detail`

Adding a 5th doc type is **zero code change**: add a `Doc Types` row + its `Placeholder Map` / `Required Fields` rows, create the template Doc, paste its ID.

## Configuration knobs

| Where | Name | Default | Purpose |
|---|---|---|---|
| `Code.gs` constant | `CONFIG_SHEET_ID` | *(blank)* | Admin Config spreadsheet ID. **Must be set.** |
| Script Property | `FOLDER_URL_COLUMN_NAME` | `Project Folder` | Header of the column holding the project's Drive folder URL. |

## Templates

Four Google Docs with `{{snake_case}}` placeholders matching the `Placeholder Map`. Location isn't enforced — they're referenced only by Doc ID in the Config sheet. The folder is treated as a precondition; Doc Gen never creates the project folder (that's upstream — see `Job Number Creation Form/`).

## Troubleshooting

- **"CONFIG_SHEET_ID is not set"** — fill the constant in `Code.gs` and save.
- **"Config tab … not found"** — run `initializeConfigSheet` from the editor.
- **Generate disabled, "Project Folder … blank/invalid"** — fix the row's folder URL, then click Refresh.
- **Generate disabled, missing fields listed** — populate them on the sheet row, then Refresh.
- **One doc ❌, others ✅** — expected on a bad Template Doc ID; check the error in the sidebar and the `error` row in the Activity tab. The per-project Activity Log Doc only records successes.
- **Shared-drive folder fails** — confirm the Advanced Drive Service is added (step 3) and the manifest was applied (step 2).

## Working with this code

Per repo convention (`../CLAUDE.md`): the Apps Script web editor is not the source of truth — edits made there must be copied back into this folder to stay versioned. Config constants (IDs, tab names) live at the top of `Code.gs`; secrets never go in source.
